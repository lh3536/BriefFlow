# Input / Output Agent changes

## Old

- `parse_user_request(text)` 返回四个字符串列表；空白字符串抛出 `ValueError`。
- 排除片段主要识别中文标点，可能吞掉同一句中后续的正向需求。
- `build_brief(preference, ranked_items)` 返回 `preference`、`total_items`、
  `recommended_items`，没有摘要；返回内容与调用方共享可变对象。

## New

- 两个函数名称、位置、必需参数和字典返回类型不变，Router 无需修改。
- 空白字符串返回四个空列表。未知或模糊需求只保留识别出的条件；完全未知时
  返回四个空列表，不虚构偏好。非字符串仍抛出 `ValueError`，表示调用方类型错误。
- 规则支持 Unicode 标点规范化、中英文标点，以及“不要”“排除”“不考虑”
  “不想要”“不想做”“不想找”“不接受”“避免”等排除表达。
  “但/不过/想找/希望/只要/要找/需要”可结束排除片段，恢复正向解析。
- 地点按广州、深圳、香港、澳门顺序去重；“广深”指广州和深圳，“港澳”指香港
  和澳门，“粤港澳”保持原演示约定，指上述四城。其余类别及关键词词表保持不变。
- 排除词仍限于销售、客服、保险、地推、电话营销。此规则解析器不支持任意
  否定、否定城市、双重否定或完整语言理解；不会宣称已解析专业资格或年级。
- Output 新增字符串 `summary`，例如“根据你的需求，本次找到 9 条匹配信息，
  其中 4 条高度匹配。”高度匹配仅为展示口径：已有有效分数在 80–100 之间。
  缺失、非数值、布尔值、非有限值或超出 0–100 的分数不计入高度匹配；
  不修复或重写它们。输入数据需遵守原 JSON-compatible 数据契约。
- 无结果时输出 `total_items: 0`、`recommended_items: []` 和明确的无结果摘要。
- 对 Preference 和推荐记录做深复制，保持顺序、所有字段及原值，包括
  `match_score`、`deadline`、`source` 和嵌套数据；不重新排名、不截断。
- 不使用 LLM、API Key、网络或额外依赖。规则路径始终可用，输出字典可直接
  用 `json.dumps()` 序列化；summary 是独立字段，不混入 Preference。

## Reason

满足空输入不中断流程和新增摘要的要求，同时保持 Router 现有调用兼容。
旧测试中“空输入抛异常”和“输出恰好三个字段”的断言与新要求冲突，因此仅
更新这些直接相关的断言；其他既有行为仍做回归验证。返回副本可避免调用方
后续修改输出时意外更改传入的推荐数据。

此文档补充原 V0.1 架构说明；空输入行为和输出字段以本变更说明为准。
